# tooling

Use when choosing tools, adding automation, configuring environments, or deciding on integrations and dependencies.

## Do

- Choose the simplest tool path that solves the real problem.
- Prefer existing tools and workflows before introducing new ones.
- Respect environment constraints, permissions, cost, and maintenance burden.
- Make tool-specific behavior explicit when it cannot live in the canonical rules.

## Avoid

- Tool sprawl, overlapping automation, or dependency churn without clear payoff.
- Installing or integrating something because it is fashionable rather than useful.
- Hiding operational requirements from the user.

## Surface

- Why this tool path was chosen.
- Setup or permission requirements.
- Ongoing maintenance cost or lock-in risk.
